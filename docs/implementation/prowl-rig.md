# Prowl's player rig

Only the greeter uses Prowl. The original `prowl_hytale.blockymodel` and texture remain unchanged in Eternia, and no Aetherhaven asset is edited. `Prowl_PlayerRig.blockymodel` is the generated playable rig used by `Eternia_Prowl`.

The generated rig follows the installed Hytale player's bone names and parent hierarchy. Its joint positions follow Prowl's anatomy, with player bone orientations; the pelvis uses the actual hip joint at 50 model units. Original shapes are re-expressed under those bones with inverse parent transforms. Head geometry follows `Head`; the actual neck follows `Neck`; eyes, eyebrows and mouth receive the standard animation target names. Eyelid geometry remains directly on its named bone so native shape-stretch tracks affect it.

Run `python scripts/rig-prowl.py --check` to verify reproducibility, or omit `--check` to regenerate after a deliberate source change. `--assets path/to/Assets.zip` selects a different installed Hytale asset pack. The proof file records the original model/texture hashes, the 40 unchanged shapes, their destinations, bounds and sample animation poses. Generation compares every shape's UV/geometry object and transformed vertices; the independent Java test compares full world transforms using JOML and fixed anatomical coordinates.

Hytale child nodes inherit the parent's **rotated shape offset**, even when the parent shape type is `none`. The initial generator omitted this offset, producing a pelvis at 25 instead of 50 units and overlapping leg/torso meshes. Its initial proof made the same incorrect assumption. The corrected calculation follows native `BlockyModelBoundsParser`: `parent × translation(position) × rotation(orientation) × translation(shape.offset)`. Shape stretch affects only the node's own geometry. Separate regression cases cover shapeless offsets, rotated offsets, and non-inherited stretch. The original and corrected bounds both extend from approximately -0.9365 to 122 units vertically; no overall scale or geometry change conceals the error.

The generator also previews the installed Idle and Walk clips at 13 sample times each. It checks leg segment transforms and standing height, and verifies that the actual eye meshes move under an eye-look clip. These calculations exercise additive animation deltas and catch rig compression; they are not a substitute for the client's exact animation blending and rendering.

Run `node website/scripts/prowl-rig-preview.js` with the website dependencies installed to render the original and corrected models through Eternia's actual viewer, using one camera, texture and character scale. It saves `website/test-output/prowl-rig-comparison.png`. If `build/prowl-before.blockymodel` exists, it also includes that saved earlier rig for comparison. The check compares the viewer's resulting bounds; it does not open a game server or use an account.

Native acceptance also uses `BlockyModelBoundsParser` on the corrected rig and a temporary original-model reference. The original has a hidden Belly mesh with visible torso/head descendants; the native bounds helper incorrectly prunes that whole subtree. The test-only reference treats hidden meshes as shapeless parents while preserving their offsets and descendants, matching the viewer's visibility behavior. The original resource is never rewritten or registered as that reference.

Native player body animation sets are inherited. Nearby-player head watching and head camera targets are explicit. Passive eye clips target Prowl's new eye/eyebrow bones. Native blink clips are copied with visible eyelid-height changes retargeted from the native seven/five-unit quads at 0.1 bind stretch to Prowl's existing eight/four-unit quads. The texture atlas is untouched. Atlas-specific native talking animations are intentionally not added: their mouth UV offsets refer to Hytale's player atlas and need separate retargeting before they can be used with Prowl's texture.

Connected-client acceptance: observe Prowl at rest and while walking around him; check eyes, blink, head tracking and idle arms; confirm the original appearance and texture are unchanged. Test the interaction prompt with a rebound Use key. Server asset loading and bind-pose proofs do not substitute for this animation and UI review.
