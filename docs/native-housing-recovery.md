# Native housing snapshots and recovery

New claims capture an immutable native baseline before players can build. The baseline spans the actual fixed world range `ChunkUtil.MIN_Y` through `ChunkUtil.HEIGHT`, including air; the outline's visual height is not a build limit. Protected road and portal columns are excluded. Existing plots without an original baseline or placed-object ownership records require migration review; their current terrain is never guessed to be the original terrain.

Snapshots are stored below the plugin data directory in `housing-snapshots`. Every snapshot is flushed to disk, atomically renamed, hashed with SHA-256, read back, and passed through the native prefab serializer/deserializer before it authorizes a destructive operation. Snapshot envelopes carry explicit empty-fluid semantics because Hytale's serializer omits empty fluids. Blocks, rotation, filler, support, containers and serializable block components are preserved. The native `BlockStateInfo` location cache is rebuilt at the destination; any other nonserializable component is rejected. Never delete `.pending` files or change snapshot hashes to clear an error.

`NativeRelocationCoordinator.captureBaseline(plugin, world, plot)` is called on the world thread before claim activation. `pack(world, owner, operationId, forced)` captures the entire current plot, computes player changes against its baseline, splits proven guild objects into guild-owned packed custody, restores the original source terrain, verifies the result, saves affected native chunk columns, and only then acknowledges `PACKED`. The owner retains their housing slot. A normal move reserves the move credit; a forced guild return does not. `restore(world, actor, owner, operationId, rectangle, groundY, scope, paid)` validates the new topology and entitlement, snapshots destination terrain, translates all changes by the selected ground elevation, rejects vertical clipping and protected columns, then verifies and saves the destination before final activation consumes the credit.

The native placement adapter handles block prefab content, including stored container components, and the reviewed decorative item entity shape used by the shipped Potion Shelf. The supported entity requires `Prop`, `BlockEntity`, `Item` (one matching item), `PreventPickup`, `PreventItemMerging`, `Transform`, `EntityScale`, `UUID`, and `PrefabCopyable`; Eternia adds its placement-instance marker. Other persistent components, unresolved components, moving/physics gameplay state, nested child prefabs, and unknown transient components are rejected before destruction. This does not establish support for arbitrary NPCs or entities with inventories.

`NativeDecorativeEntities` remaps UUIDs when instantiating a new catalog prefab and persists those identities in the verified after-image before spawning. Pickup, whole-property packing and restore preserve the recorded UUIDs and instance ownership. A duplicate live UUID or missing expected entity aborts before deletion. The adapter applies Hytale's documented v0 BlockEntity anchor/scale migration before hashing. It strips only rebuilt native caches: NetworkId, BoundingBox, ItemPhysics, DynamicLight, SnapshotBuffer, tracker visibility and Dirty save bookkeeping. Native holder/setup systems rebuild those on load. All remaining components must retain the same archetype through serializable cloning and exactly round-trip through their native codec.

Packing explicitly removes and marks saved section membership; plain native `UNLOAD` alone would not persist deletion. The adapter waits for a cubic storage entity-row tombstone before the UUID can be restored. Fresh entities are forced dirty and cubic entity bodies are saved before chunk-column membership and the final backing-store flush. Legacy `ChunkColumn`/`EntitySection` serializable clones embed complete entity holders in the column. Snapshot preflight rejects affected chunks/sections/entities with in-flight saves and sections still holding unloaded entities, so an older asynchronous save cannot overtake the acknowledged write. Verification failures retain a local `verify-<uuid>.json` expected/actual diagnostic alongside the immutable snapshots.

Restoration supports retaining the plot size or increasing each dimension with an even whole-block difference. Personal 24→32 uses a four-block inset; guild 48→64 uses eight. The house, additions, props, fluids and entity positions all move by the same horizontal center offset and selected ground-height difference, and native provenance descriptors move with them. Shrinking and incompatible rectangle turns remain rejected. Newly exposed terrain is preserved through the destination baseline. Cubic or out-of-band worlds, partially loaded sections, unknown assets, unproven entities and conflicting ownership edits are rejected before removal. Fixed-height chunk columns must be fully loaded and attached. Large guild snapshots run synchronously on the world thread and need native memory/performance qualification before a public server launch.

Building placement requires an owned `eternia:house/<catalogId>` unlock. Prop placement reserves an owned `eternia:prop/<catalogId>` quantity. Physical token metadata is never authority. Picking up an object saves its actual captured cells and marks its provenance `PACKED`; its quantity stays reserved, and no duplicate token is issued. Housing inventory should include these packed instances. Selecting the same catalog entry reuses packed custody before reserving another grant. Packed object rotation currently stays at its original orientation. Objects with later overlapping placements must be unpacked in reverse order or moved with the whole plot. Edited block identity that cannot be attributed safely is rejected; stored container contents are retained.

Guild departure jobs are leased from `GuildService` after the durable 48-hour deadline. `GuildDepartureWorker` runs once per minute, evacuates occupants through the configured safe hub arrival, retries after teleport, and acknowledges the job only after the native operation reaches `PACKED`. An unavailable world, blocked hub destination or missing snapshot prevents false completion. Guild returned objects remain owned by the guild and carry their exact snapshot reference in `ProvenanceService.Instance.snapshotRef`; they are never granted to the departing player.

The housing menu lists `provenance.ownedInstances(owner)` so packed custody remains discoverable after its former player plot is packed. Authorized owners of attached personal plots see a separate **Guild decorations** inventory; guild estate builders see the guild inventory. The selected owner is stored in the server-side `PropPlacementSession`, displayed in the preview, and passed to `NativePlacementTransactions.place(..., custodyOwner)`. Physical token metadata and UI fields cannot choose that owner. Opening, selecting, previewing and committing recheck current matching membership, attachment, plot permission and `inventory.reserve_for_build`. Guild inventory permission does not grant access to another member's private plot.

Placement uses `housing.prop.place` and packaging uses the seeded `housing.prop.pack` capability. Guild inventory also requires `inventory.reserve_for_build` at pickup; role revocation or guild departure invalidates an already open preview. Packing re-resolves the original provenance owner, leaves the quantity reserved, and returns the saved instance to that owner's inventory. A guild decoration placed on a personal plot therefore returns to the guild, including when another authorized builder placed it originally. The pickup journal belongs to the edited property's owner so an interrupted guild-custody pickup locks that personal property for recovery. `HousingCustodyTest` covers the permission matrix, seeded architect capability, revocation/departure and preserved guild custody without minting another quantity.

Supported decorative entities are segregated by the exact recorded placement instance; unrelated personal entities remain in the player's snapshot. A guild container with nonempty contents is rejected before segregation: ownership of the container does not prove ownership of each item inside it. An administrator must segregate those items with ownership evidence before the forced return can finish.

An exception after world mutation marks the journal `RECOVERY_REQUIRED`; protection must keep the property locked. `inspect(operationId)` provides read-only hash verification and journal evidence. `recoverPackToSource(world, owner, operationId)` is an explicit administrator action for an interrupted source pack whose slot is still `MOVING`. It accepts only source cells matching either documented preimage or baseline, restores the verified original property, verifies and flushes it, restores provenance and native plot metadata, then cancels the move and releases the reserved credit. Unexpected edits keep the lock. Interrupted destination restoration and placement/pickup metadata conflicts remain locked for snapshot-guided administrator recovery; automatic replay must not guess whether a native write completed.

Validation: unit tests cover immutable snapshot replay, tamper rejection, interrupted writes and path confinement. The native test ladder must additionally exercise a house with furniture and container items, a fluid-only change, a basement and high addition, a move to higher/lower terrain, guild-owned furniture inside a personal house, an occupied forced return, and process termination at each journal transition. Verify both source and destination after a fresh server load and compare exact item/component counts. A compile or filesystem test does not substitute for these game-runtime checks.
